# Threat model

What can go wrong, what defends against it, which test proves the defence, and what is **not** defended. A defence is only listed if a test exercises it. "Residual" is the honest part.

| # | Threat | Defence | Tests | Residual risk |
|---|---|---|---|---|
| 1 | **Prompt injection** through customer text (answers, payee names, notes) trying to make the AI release or approve something | The AI has no tools. Customer text is redacted, screened, delimited as untrusted data and never obeyed; output must be a validated schema; a deterministic policy engine owns outcomes; flags can only add friction | `test_llm_gateway.py` (injection flagged, delimiter cannot be forged, an obeying reply is rejected), `test_screening_workload.py` (injection in a payee name), `test_agents.py` (final reading step), `test_hardening.py` (zero-width and look-alike characters), sandbox report (attacker personas) | Injection screening is a keyword heuristic and will miss paraphrases. The real defence is structural (no tools, schema, policy). |
| 2 | **Forbidden or irreversible action** by an agent | Risk tiers T0 to T3; signed, expiring capability tokens; T3 never allowed by policy alone; approvals are bound to exact arguments and used once; shadow mode never acts | `test_tools.py` (tier rules, approval covers exactly one execution of exactly those arguments, shadow mode, a property test), `test_hardening.py` (one approval authorises one execution under a race) | T3 acts on a sandbox ledger only; there is no real money movement to test. |
| 3 | **Ledger tampering** (edit, delete, forge) | Hash chain per tenant plus a head row; `GET /v1/audit/verify` | `test_ledger.py` (edit, middle delete, last delete, forged tail all detected) | Tamper-evident, not tamper-proof: someone who controls the database and recomputes every later hash is detected only if the head hash was stored elsewhere. No external anchoring yet. |
| 4 | **Duplicate or replayed requests** | Idempotency keys (format-checked) on decisions, events and tool calls; reuse with a different body is a 409 | `test_decisions.py`, `test_concurrency.py` (parallel requests, one effect), `test_hardening.py` (key format) | Keys are client-chosen; a client that reuses keys across tenants is separated by tenant scope only. |
| 5 | **Races** that decide or consume something twice | Single conditional `UPDATE ... WHERE status = ...` and a row count decide the winner | `test_hardening.py` (an approval decided once; one approval used once), `test_security.py` (daily budget under 12 threads), `test_cases.py` (one disposition per case) | Race tests run on PostgreSQL only; SQLite skips them. Fixed bugs were found by a flaky test, so further races may exist in code not yet stress-tested. |
| 6 | **Personal data sent to a model** | Pattern redaction (email, card with Luhn check, phone, IBAN, ID, street address) and a name model, before any provider call; fixed 4,000-character cap | `test_llm_gateway.py` (canaries always redacted, idempotent), `test_hardening.py` (full-width digits, lower-case IBAN, zero-width characters), `docs/reports/redaction.md` | **Names still leak:** 88% of US-style and 73% of non-US names were fully removed in the test; 9% to 18% were left in place. Non-Latin scripts and unusual address formats are untested. |
| 7 | **Cross-tenant access** | Tenant comes from the API key, never from the request; every query filters on it | `test_decisions.py`, `test_tools.py` (another tenant cannot approve), `test_cases.py` (every case endpoint returns 404 to another tenant) | One database for all tenants; isolation is by query filter, not by database or row-level security. |
| 8 | **Privilege misuse** | Roles per key: viewer reads, analyst acts, admin imports; a typo in a role fails at startup instead of becoming admin | `test_security.py` (roles, other doors, whoami, role parsing) | Keys are static strings from the environment: no rotation, expiry or audit of key use beyond actions in the ledger. |
| 9 | **Poisoned or biased feedback labels** | Every label records actor and whether the analyst was a person or simulated; a case can be decided once; truth is hidden until a decision | `test_cases.py`, `docs/reports/flywheel.md` (how noise and collection strategy change the model) | There is **no automatic defence** against a bad analyst: at 20% analyst error some strategies were worse than no feedback. Labels are not signed and no holdout check runs before retraining. |
| 10 | **Cost abuse and overload** | Per-key rate limit, request-size limits (256 KB body, 64 KB objects), daily AI request and token cap in the database, per-run cap, deadlines and a deterministic fallback | `test_security.py` (429 with Retry-After, caps shared between instances and across a restart), `test_hardening.py` (oversized bodies), load report | The rate limiter is per process. A Content-Length-less request is only caught after the body is read; put a size limit at the proxy. |
| 11 | **Secrets in the repository** | `.env` is git-ignored; keys are never printed; the staged diff was scanned for key values before each public push | scan run before each push (not a test in the suite) | Two API keys were pasted into a chat during development: **rotate them** before any public demo. |
| 12 | **Console attacks** (script injection, key theft) | React escapes all text; reports render without raw HTML; no cookies; the key lives in the tab's session storage | `console/e2e/console.spec.ts` covers behaviour, not attacks | A script injection bug would expose the key in session storage. The console has no real login: it is a demo client. |
| 13 | **Supply chain and data licences** | Raw data is downloaded by checksum-verified script and never committed | `test_pipeline_units.py`, `test_real_data.py` | Python dependencies are not pinned or hashed. Licence terms for OFAC, ULB and Elliptic are **unconfirmed**. |
| 14 | **Misleading results** (simulated shown as real) | Provenance chip on every report and case; generated reports; limits section in each | `console/e2e/console.spec.ts` (chips), `test_api.py` (report provenance) | A reader can still skip the chip. |

## Not covered at all

Denial of service at the network layer, TLS termination and database encryption (left to the host), insider threats with database access, side channels, and any compliance claim (this project makes none).
